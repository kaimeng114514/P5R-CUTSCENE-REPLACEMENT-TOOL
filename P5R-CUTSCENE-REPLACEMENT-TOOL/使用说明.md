# P5R 过场动画替换工具 · 使用说明

一个面向《女神异闻录 5 皇家版》（Persona 5 Royal, PC/Steam）的过场动画一键解包、预览与替换工具：

1. **一键导入 MOVIE_JE.CPK**，自动解包全部过场动画（.usm）
2. **直接预览** —— 解包后生成 m2v 原流 + 音轨缓存，点击列表即可播放
3. **替换视频 & 生成 Mod** —— 导入自己的视频，一键打包成 Reloaded-II 可加载的 Mod

---

## 一、快速开始

1. 解压工具到任意目录
2. 双击 **`P5R过场动画替换工具.exe`** 即可使用
3. 无需安装 Python、FFmpeg 或任何运行库，全部内置

---

## 二、快速上手（三步）

### 第 ① 步：导入 CPK

1. 菜单栏点「文件 → 导入 MOVIE_JE.CPK」，选择 P5R 目录下的 `CPK\MOVIE_JE.CPK`。
   （工具只识别 MOVIE_JE.CPK，不会误包其他 CPK 文件。）
2. 弹出进度窗口，依次经历三个阶段：
   - **导入 CPK**：读取文件列表
   - **解包 USM**：全部过场解包到本地
   - **生成预览**：并行生成 m2v 原流 + 音轨缓存
3. 三阶段完成后，左侧列表显示全部过场，点击即可直接预览。

> 再次启动工具会自动恢复上次导入的 CPK 和替换记录，缓存已就绪时秒进列表，无需重新解包。

### 第 ② 步：预览

1. 在左侧列表**单击**选中过场 → 右侧「视频预览」自动载入首帧。
2. 点 **▶ 播放** / **⏸ 暂停** / **■ 停止**，画面下方显示进度。
3. **无音轨**过场列表会标注"无音轨"，播放时只有画面。
4. 如果某过场已被替换，勾选 **"播放替换后视频"** 即可在预览中对比替换效果。
5. 点 **「导出 MP4…」** 可把当前过场导出为原始分辨率 H.264 + AAC 高质量 MP4 文件。

### 第 ③ 步：替换 & 生成 Mod

1. 左侧列表选中要替换的过场。
2. 在下方「待替换视频预览」区点 **「导入视频…」**，选择你自己的视频（mp4/mkv/webm/mov 等）。
3. 点 **「替换所选视频」**，列表中该过场会标注"已替换"及替换文件名。
   - **「撤销替换」**：取消该过场的替换
   - **「撤销导入视频」**：清空当前导入的待替换视频
4. 点 **「一键生成 Mod」**，在弹窗中输入 Mod 名称和简介，选择输出目录
   （可自定义，或选择工具内置的 Reloaded-II Mods 目录）。
5. 生成完成后，启动 Reloaded-II 加载游戏即可。

> 支持同时替换多个过场，全部打包到同一个 Mod 中。

---

## 三、Mod 安装与使用（Reloaded-II）

工具已内置 Reloaded-II，无需单独安装：

1. 点工具栏 **「启动 Reloaded-II」** 启动模组加载器。
2. 点 **「打开 Mod 文件夹」** 可直接打开 Reloaded-II 的 Mods 目录。
3. 在 Reloaded-II 中勾选启用你的 Mod，启动 P5R 即可。

生成的 Mod 结构：

```
<Mod输出目录>\<Mod名>\
├── ModConfig.json                  ← Reloaded-II 识别用
└── P5REssentials\CPK\data_movie.cpk\MOVIE\
    └── movXXX.usm                  ← 替换后的过场视频
```

## 五、常见问题

**Q：第一次导入要多久？**
首次导入需要解包约 2-3GB 的 CPK 并生成预览缓存，时间取决于硬盘速度（SSD 较快，HDD 较慢）。再次启动直接秒进列表，无需重新解包。

**Q：替换后游戏内过场没变？**
1) 确认 Reloaded-II 中 Mod 已勾选启用；2) 确认工具生成的 Mod 在 Reloaded-II 的 Mods 目录中；3) 检查日志。

**Q：替换后的视频比原版长/短？**
支持任意时长的视频，不会自动加速或裁剪。双音轨过场（如 MOV001）已修复时长截断问题。

**Q：预览声音异常或没有声音？**
- 双音轨过场（如 MOV001 赌场）默认播放日文配音（音轨二）。
- 后段过场（MOV092~097 等）使用 MPEG-2 + ADX 音频格式，工具已自动识别并解码。
- 如果仍无声，确认列表中该过场未标注"无音轨"。

**Q：列表滚动不到底部？**
已修复滚轮滚动 bug，现在鼠标滚轮可以一直滚到列表最后一项（MOV318）。

**Q：生成 Mod 速度？**
VP9 编码已优化为实时模式，单条约 10-30 秒（取决于视频时长），不牺牲画质（CRF 21）。

**Q：杀软报毒？**
PyInstaller 打包的 exe 可能被误报，添加信任即可。

## 六、技术调查报告（供 Mod 开发者参考）

本章节记录开发过程中对 P5R PC 版过场动画格式的逆向发现，供后续 Mod 制作者参考。
**更详细的完整调查报告请查看工具内「帮助 → 技术调查报告」。**

### 6.1 文件格式与加密

- **过场容器**：CRI USM（CRI Movie 2），PC 版文件位于 `CPK\MOVIE_JE.CPK` 内的 `MOVIE\*.USM`。
- **加密 Key**：PC 版统一使用 **0x2341683d2fdba6**。此 key 由社区逆向流出，所有 USM 文件共用。
- **视频编码**：VP9（IVF 封装），stream index = 0。部分后段过场（MOV092+）为 MPEG-2。
- **音频编码**：HCA（CRI 的无损压缩音频格式），stream index >= 1。部分后段过场为 ADX 格式。
- **双音轨**：部分过场包含两条 HCA 音轨（英文 + 日文），**日文配音为最后一条**（index 最大的 HCA）。工具自动选择日文音轨。

### 6.2 已知工具链对比

| 工具 | 用途 | 优劣 |
|---|---|---|
| **CriCodecs**（Python 库） | USM/CPK/HCA/ADX 解包、解密 | 纯 Python 调用，无需外部进程，速度最快；但 C++ 底层不支持中文路径，需用 Python 文件句柄绕过 |
| **crid_mod.exe**（CRI Demux Tool v1.02-mod） | USM 解复用 | 独立 exe，兼容性好；但启动进程慢，对个别跨 chunk 帧解密更准确 |
| **FFmpeg** | VP9 编码转码、首帧提取 | 实时模式 CRF 21 不牺牲画质；NVIDIA NVENC **不支持 VP9**，只能用 CPU 编码 |
| **foobar2000 + vgmstream 插件** | HCA 音频播放/转换 | 手动验证用，工具内已集成 HCA 解码 |

### 6.3 关键技术坑点

1. **中文路径问题（最重要）**：CriCodecs 的 C++ 层在 Windows 上**不支持非 ASCII 文件路径**。如果工具安装在含中文用户名的目录下，直接传路径字符串给 `usm.load()` 会静默失败（不报错但返回空数据）。**解决方案**：用 Python 的 `open(path, 'rb')` 文件句柄传给 `usm.load(fileobj, key=...)`，绕过 C++ 路径解析。pygame/SDL2 同样不支持中文路径加载 wav，需复制到 ASCII 临时目录。

2. **MOV001 赌场过场时长截断**：原版 MOV001 的播放时长由游戏脚本硬编码。替换为更长的视频后，游戏会在原版时长处截断进入实机画面。**解决方案**：需要 P5R FileId Redirector Mod 配合，hook CRI 文件系统的时长查询函数，让游戏按替换视频的实际时长播放。**不建议自动加速/减速视频**，会严重影响观感。

3. **cricodecs 漏解密帧**：部分过场在特定时间点画面定格，但音频正常。这是 cricodecs 对跨 chunk VP9 帧漏做 MaskVideo 解密导致的。**解决方案**：对此类帧用 crid_mod.exe 单独解包修复。

4. **ADX 音频与字幕流**：后段过场（MOV092~097）不是 VP9+HCA，而是 MPEG-2+ADX 格式。音频流的 filename 字段是 `.avi` 不是 `.hca`，且 USM 末尾可能附一条 `.txt` 字幕流。**必须按二进制魔数识别格式**（HCA: `48 43 41 00`，ADX: 首字节 `0x80`），不要依赖文件扩展名。

5. **多线程与 GIL**：CriCodecs 是 nanobind 编译的 C 扩展，不释放 GIL。并行数超过 3-4 时反而因 GIL 争用导致 UI 卡顿。建议预览生成并行数设为 3。

6. **PyInstaller 打包**：CriCodecs 是单个 `.pyd` 文件，PyInstaller 的自动依赖分析无法发现。必须在 `.spec` 文件的 `binaries` 中手动指定 `.pyd` 文件路径到 `cricodecs/` 目录。

7. **子进程弹窗**：打包成 exe 后，所有 subprocess 调用（ffmpeg 等）必须加 `creationflags=0x08000000`（CREATE_NO_WINDOW），否则会闪黑窗。

### 6.6 编解码参数

- **VP9 编码**：CRF 21（视觉无损），cpu-used 7，deadline realtime
- **音频**：AAC 192kbps，不重采样
- **不牺牲音视频质量**：CRF 21 不可降低，音频不重编码
- **预览**：直接播放 IVF/VP9 原流，零重编码
